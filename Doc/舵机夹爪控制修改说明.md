# 舵机夹爪控制修改说明

本说明仅基于当前工程中已经落地的代码整理，只记录最终保留的修改点，不包含中途验证方案和临时调试结论。

## 修改文件总览

本次夹爪控制相关的最终修改文件如下：

- `Project/Fire-F407.uvprojx`
- `User/main.c`
- `User/usart/bsp_debug_usart.c`
- `User/gripper/bsp_gripper_uart.h`
- `User/gripper/bsp_gripper_uart.c`
- `User/gripper/bsp_bus_servo.h`
- `User/gripper/bsp_bus_servo.c`
- `User/gripper/bsp_gripper.h`
- `User/gripper/bsp_gripper.c`
- `User/stepper/bsp_device_usart_ctl.h`
- `User/stepper/bsp_device_usart_ctl.c`

## 各文件修改点

### 1. `Project/Fire-F407.uvprojx`

- 将 `User/gripper/` 下的夹爪串口、舵机协议、夹爪控制文件加入工程编译。
- 将原来的 `bsp_stepper_usart_ctl.c` 工程入口直接切换为 `bsp_device_usart_ctl.c`，使工程中的命令分发文件名与当前职责一致。
- 增加 `--no-multibyte-chars` 编译选项，避免中文字符串相关的多字节字符编译告警。

### 2. `User/main.c`

- 将串口命令分发头文件切换为 `bsp_device_usart_ctl.h`。
- 在系统启动阶段增加 `BusServo_Init()`，完成夹爪 UART5 通信初始化。
- 保持原有调试串口主循环不变，在现有 `DealSerialData()`、`Device_Task()`、`Device_ReportDone()` 框架内接入夹爪设备。

### 3. `User/usart/bsp_debug_usart.c`

- 扩展 `HAL_UART_MspInit()`，在保留 `USART1` 调试串口初始化的基础上，增加 `UART5` 的 GPIO 复用初始化。
- 夹爪串口使用 `PC12(TX)`、`PD2(RX)`。
- 这样可以继续复用当前工程的 HAL UART 初始化入口，不额外改动底层时钟和 MSP 框架。

### 4. `User/gripper/bsp_gripper_uart.h`

- 新增夹爪专用串口硬件定义。
- 固定夹爪通信口为 `UART5`，并定义 `PC12`、`PD2` 的端口、引脚和复用功能。
- 对外提供夹爪串口配置、收发、清空接收缓存接口。

### 5. `User/gripper/bsp_gripper_uart.c`

- 新增夹爪串口收发实现。
- 使用 HAL 阻塞发送和阻塞接收，满足当前问答式舵机协议的短包通信需求。
- 提供接收缓存清空接口，避免上一帧残留数据影响下一次应答解析。

### 6. `User/gripper/bsp_bus_servo.h`

- 新增舵机协议层头文件。
- 定义夹爪当前使用的寄存器地址、指令字、默认 ID 和状态结构体。
- 对外提供 `ping`、寄存器读写、状态读取、扭矩开关、位置运动接口。

### 7. `User/gripper/bsp_bus_servo.c`

- 新增舵机协议封包、校验、收包和寄存器读写实现。
- 按 `FF FF ID LEN INST PARAM... CHKSUM` 格式发送指令，并按应答包格式解析返回。
- `BusServo_ReadStatus()` 固定读取 `0x38` 开始的基础 8 字节状态，避免扩展寄存器读取失败影响动作反馈。
- 对 `0x3C` 当前负载做专门解码，只取低 10 位幅值，并处理方向位，避免将原始值直接当作负载阈值导致误判。
- 补充 `0x41` 舵机状态、`0x45` 当前电流的单独读取接口，供状态显示使用。

### 8. `User/gripper/bsp_gripper.h`

- 新增夹爪业务层头文件。
- 固定当前夹爪标定范围：
  - 最大张开位置 `800`
  - 闭合位置 `2048`
- 定义夹爪速度、堵转判定、`grip` 负载阈值、`release` 退开量等控制范围。
- 对外提供 `open`、`close`、`move`、`grip`、`release` 等业务接口。

### 9. `User/gripper/bsp_gripper.c`

- 新增夹爪业务层实现，负责把串口寄存器操作组织成可直接调用的夹爪动作。
- `open`、`close`、`move` 统一改为带反馈的运动流程：发送目标位置后轮询状态，到位返回 `ok`，持续堵转则关闭扭矩并返回 `stall`。
- `grip` 改为基于 `0x3C` 当前负载的分步夹取，不再单纯依赖转矩限制；当负载连续达到阈值后停止继续闭合并保持当前位置。
- `release` 采用当前确认过的流程：先关闭扭矩，再读取当前位置，重新打开扭矩后退开一小段距离。
- 补充位置、速度、夹持阈值的范围校验，防止非法参数直接下发到舵机。

### 10. `User/stepper/bsp_device_usart_ctl.h`

- 新增“多设备串口命令分发”头文件，作为当前正式的命令分发接口。
- 将原来只面向步进电机的入口扩展为统一管理 `mtor1`、`mtor2`、`clamp`、`vacum` 的设备层接口。

### 11. `User/stepper/bsp_device_usart_ctl.c`

- 新增正式的多设备串口命令分发实现文件，承接原 `bsp_stepper_usart_ctl.c` 的功能并扩展夹爪控制。
- 保留原有步进电机命令，同时新增 `clamp` 命令集：
  - `clamp ping`
  - `clamp status`
  - `clamp open`
  - `clamp close`
  - `clamp move [position] [speed]`
  - `clamp grip [load] [speed] [step]`
  - `clamp release [delta] [speed]`
- `status` 总览命令中增加夹爪完整状态输出，显示位置、速度、负载、电压、温度、电流和舵机状态。
- `?` 帮助和启动提示中补充了夹爪命令、参数范围和单位说明。
- 对较长的命令处理和状态反馈逻辑增加中文注释，方便后续维护。

## 最终功能结果

当前工程已经具备以下夹爪控制能力：

- 通过 `UART5` 与夹爪驱动板进行问答式串口通信。
- 查询夹爪在线状态和运行状态。
- 执行张开、闭合、指定位置移动。
- 基于负载反馈执行夹取。
- 在位置类动作遇到持续堵转时自动卸力，避免障碍物移除后继续追目标。
- 在总览 `status` 和单独 `clamp status` 中输出夹爪详细状态。
