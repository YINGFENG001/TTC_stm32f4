# 步进电机运行中动态调速方案

本文记录 `mtor1/2 move +0/-0` 连续运行期间动态修改 `rpm` 的当前实现方案。代码已经新增底层状态机支持：连续运行中执行 `mtorX rpm [value]` 会更新当前运行目标速度，并按当前 `set` 保存的 `accel/decel` 平滑过渡；`rpm 0` 会减速到停止，`rpm N` 目标方向为 `CW`，`rpm -N` 会先减速再反向到 `CCW` 并升到 `N rpm`；定长 `move [rev]` 运行期间仍不支持动态调速。

## 目标行为

```text
mtor2 move +0
mtor2 rpm 40
mtor2 rpm 60
mtor2 rpm 20
mtor2 stop
```

- 连续运行中执行 `rpm` 不再只保存参数，而是调整当前运行速度。
- `rpm 0` 表示减速到停止，不把保存的默认 rpm 改成 0。
- `rpm N` 表示目标方向为 `CW`；`rpm -N` 表示目标方向为 `CCW`，先减速到接近停止，再切换方向并升到 `N rpm`；保存和打印的 rpm 仍为正数 `N`。
- `move` 和连续运行中的 `rpm` 回显会打印 `dir=CW/CCW`，便于从串口日志直接确认目标方向。
- 调速过程按当前 `accel/decel` 逐步过渡，不瞬间跳变脉冲周期。
- 定长 `move [rev]` 运行中暂不支持动态调速，避免影响剩余步数和减速点计算。
- 空闲时执行 `rpm` 保持现有行为：只保存参数并打印当前设置。

## 原理简述

底层步进速度由 `srd[motor_id].step_delay` 和 `srd[motor_id].min_delay` 控制：

- `step_delay`：当前半周期相关延时，越小速度越快。
- `min_delay`：当前运动允许达到的最小 delay，对应目标最高速度。
- `speed_decision()` 每输出一个完整脉冲后，根据 `run_state` 更新 `step_delay`。

动态调速可以理解为：连续运行中维护一个有符号的当前速度 `current_speed_q16` 和目标速度 `target_speed_q16`，每完成一个完整脉冲后按 `accel/decel` 限幅逼近目标速度，再把当前速度换算成新的 `step_delay`。

当前版本不在中断中做浮点换算。`Stepper_SetMotorPulsesPerRev()` 会在机械参数变化时预计算 `speed-delay` 换算系数，`speed_decision()` 中只做整数定点运算。

定长 `move [rev]` 仍使用原来的 `ACCEL/RUN/DECEL/STOP` 梯形加减速逻辑；连续 `move +0/-0` 使用独立的动态速度规划逻辑，两套状态不混用。

## 代码修改点

### 1. `User/stepper/bsp_stepper_T_speed.h`

已扩展 `speedRampData`：

```c
uint8_t continuous;
uint8_t speed_update_pending;
uint32_t target_min_delay;
uint32_t target_speed;
uint32_t target_accel;
uint32_t target_decel;
int32_t current_speed_q16;
int32_t target_speed_q16;
```

用途：

- `continuous`：标记当前是否为 `move +0/-0` 连续运行。
- `current_speed_q16`：连续运行当前速度，Q16 定点，有符号，正数为 CW，负数为 CCW。
- `target_speed_q16`：连续运行目标速度，Q16 定点，有符号。
- `target_min_delay`：目标 rpm 对应的参考 delay，主要用于状态和调试记录。
- `target_accel/target_decel`：调速时使用的加减速度参数。

已新增函数声明：

```c
StepperCmdResult Stepper_UpdateRunningSpeed(uint8_t motor_id,
                                            uint32_t accel,
                                            uint32_t decel,
                                            uint32_t speed);
```

### 2. `User/stepper/bsp_stepper_T_speed.c`

在 `stepper_move_T()` 中：

- 设置 `srd[motor_id].continuous = FALSE`。
- 定长运动暂不允许动态调速。

在 `Stepper_RunContinuous()` 中：

- 设置 `srd[motor_id].continuous = TRUE`。
- 初始化 `current_speed_q16 = 0`。
- 通过 `Stepper_SetContinuousTarget()` 设置目标速度、方向、加减速度。
- 进入 `SPEED_ACCEL`，从低速按当前 `accel` 升到目标速度。

已新增 `Stepper_UpdateRunningSpeed()` 和 `Stepper_UpdateContinuousSpeedSigned()`：

- 检查 `motor_id` 有效。
- 检查电机已使能、正在运行。
- 检查 `srd[motor_id].continuous == TRUE`，否则返回 `STEPPER_CMD_BUSY` 或 `STEPPER_CMD_PARAM_ERROR`。
- 正常正数 rpm：更新 `target_speed_q16` 为正向目标速度。
- `rpm 0`：更新 `target_speed_q16 = 0`，按 `decel` 减速到停止。
- `rpm N`：更新 `target_speed_q16` 为 `CW` 目标速度；`rpm -N`：更新为 `CCW` 目标速度，先按 `decel` 减速到 0，再切换方向并按 `accel` 升速；保存的 `param.rpm` 为正数 `N`。

在 `speed_decision()` 中加入连续运行专用规划：

- `RUN/SPEED_ACCEL/SPEED_DECEL` 中如果 `continuous == TRUE`，调用 `Stepper_UpdateContinuousPlanner()`。
- `Stepper_UpdateContinuousPlanner()` 只做整数定点运算：
  - 同向升速：按 `accel` 增加 `current_speed_q16`。
  - 同向降速：按 `decel` 降低 `current_speed_q16`。
  - 反向：先按 `decel` 把 `current_speed_q16` 拉到 0，再切换 DIR 并按 `accel` 升到反向目标。
  - 停止：`target_speed_q16 = 0` 且当前速度降到 0 后进入 `STOP`。
- 根据 `current_speed_q16` 使用预计算系数换算新的 `step_delay`。

已新增状态：

```c
#define SPEED_ACCEL 4
#define SPEED_DECEL 5
```

这样不会干扰定长运动原本的 `ACCEL/RUN/DECEL/STOP` 逻辑。

### 2.1 ISR 减负和状态边界

本次同步吸收 `bsp_stepper_T_speed_core_review.md` 中的关键建议：

- `speed_decision()` 内部的 `edge_count/step_count/rest/last_accel_delay` 已移动为文件级 static 状态。
- 新增 `Stepper_ResetIsrState()`，在 `Stepper_Stop()`、`stepper_move_T()`、`Stepper_RunContinuous()` 的边界清理 ISR 状态。
- `STOP` 分支直接完成停止处理后 `return`，避免把默认 `new_step_delay` 写回状态。
- 局部变量去掉不必要的 `__IO`。
- 下一次比较值改为基于旧 CCR 累加，而不是基于当前 CNT，减少 ISR 进入延迟带来的脉冲周期抖动。
- 连续运行动态调速路径不再调用浮点 `speed-delay` 互转函数。

### 3. `User/stepper/bsp_stepper_ctl.c`

修改 `DeviceApi_StepperSetRpm()` 和 `DeviceApi_StepperSetSignedRpm()`：

- 先按当前 `gear` 做范围检查。
- 空闲时：`DeviceApi_StepperSetRpm()` 只更新 `stepper_cfg[motor].param.rpm`；`DeviceApi_StepperSetSignedRpm()` 对 `rpm <= 0` 返回范围错误，避免空闲时保存负数 rpm。
- 连续运行中：
  - 换算 `accel_internal`、`decel_internal`、`speed_internal`。
  - 调用 `Stepper_UpdateRunningSpeed()`。
  - 成功后更新 `stepper_cfg[motor].param.rpm` 为正数速度大小；`rpm 0` 不修改保存值。
- 定长运动运行中：
  - 暂不支持，返回 `DEVICE_API_BUSY`。

修改 `Stepper_CommandRpm()`：

- 当前如果运行中调速成功，打印：

```text
mtor2 setting rpm=60(1~75 rpm) dir=CW
```

- 如果定长运动运行中执行 `rpm`，打印 `busy` 或 `range_error`。

### 4. `User/ros/bsp_ros_protocol.c`

ROS 侧通过 `DeviceApi_StepperSetSignedRpm()` 设置 rpm，参数解析为有符号数，和人工串口命令保持一致。
连续运行期间，`rpm N` 表示目标方向为 `CW`，`rpm -N` 表示目标方向为 `CCW`，`rpm 0` 表示按 `decel` 减速到停止。

当前返回语义：

- 连续运行中执行 ROS `rpm [value]` 或 `rpm -[value]` 调速成功：返回 `DEVICE_API_OK`。
- 定长运动运行中执行 ROS `rpm [value]`：返回 `DEVICE_API_BUSY`。
- ROS `rpm` 成功回显附加 `value=<signed_rpm> dir=CW/CCW/STOP`。
- ROS `move` 启动成功回显附加 `dir=CW/CCW`；连续运行时附加 `continuous=1`。

### 5. 文档更新

更新 `README.md` 和 `Doc/双电机步进控制修改说明.md`：

- 说明 `move +0/-0` 连续运行期间允许 `rpm [value]` 动态调速。
- 说明定长 `move [rev]` 期间暂不支持动态调速。
- 说明动态调速使用当前 `set` 中的 `accel/decel` 作为斜坡。

## 风险和边界

- 调速状态机避免和定长运动的减速点 `decel_start` 混用，所以当前只支持连续运行。
- 运行中改 `gear/micro` 仍应保持禁止，因为会改变位置换算和底层脉冲尺度。
- 如果新 rpm 对应的 delay 非常小，需要继续受 `motor_rpm_max` 和当前 `gear` 动态范围限制。
- 若负载很大，动态升速仍可能失步；建议先用较低 `accel/decel` 测试，再逐步提高。
