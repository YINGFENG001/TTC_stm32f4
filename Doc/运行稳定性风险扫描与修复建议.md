# 运行稳定性风险扫描与已实施修复

## 当前结论

本文件只记录当前代码已经采用的运行稳定性方案，不再保留历史方案比较。

当前没有发现业务状态机中明显的无条件死循环。已经处理的重点风险包括：HAL 毫秒时间基、启动初始化顺序、串口命令接收竞态、步进 ISR 共享状态、后台监控通信误报、Fault 后永久停死。

## 风险1：HAL 毫秒 tick

当前实现已经恢复 HAL 标准 SysTick 毫秒 tick：

- `User/main.c`：启动时先调用 `HAL_Init()`。
- `User/stm32f4xx_it.c`：`SysTick_Handler()` 调用 `HAL_IncTick()`。
- `User/delay/core_delay.c`：不再重定义 `HAL_GetTick()`，DWT 只用于 `delay_us/delay_ms`。
- `User/delay/core_delay.h`：使用 `CPU_TS_TmrInit()` 初始化 DWT。
- `User/gripper/bsp_bus_servo.c`：不再从舵机初始化里接管 HAL tick。

效果：

- `HAL_GetTick()` 恢复真实毫秒级。
- `DEVICE_FAST_CHECK_INTERVAL_MS = 200U`、舵机和 Modbus UART timeout 都按毫秒工作。
- 避免 DWT 32 位计数器约 25.5s 回绕影响设备周期任务。

## 风险2：启动阶段 tick 初始化顺序

当前启动顺序：

1. `HAL_Init()` 建立 HAL SysTick。
2. `SystemClock_Config()` 配置系统时钟。
3. `CPU_TS_TmrInit()` 启用 DWT 微秒延时。
4. 初始化串口、夹爪、吸盘、按键、LED、步进电机。

效果：

- `SystemClock_Config()` 内部 HAL 超时可以依赖有效 tick。
- DWT 不再参与 HAL 超时，只承担短延时。

## 风险3：串口命令接收竞态

当前 USART 命令接收采用 active/pending 双缓冲：

- `User/usart/bsp_debug_usart.c`
  - `DebugUsart_RxByteFromIsr()`：USART ISR 字节入口，只维护 active buffer。
  - `DebugUsart_PopCommand()`：主循环取出 pending command 的本地副本。
  - pending 已被占用时，普通命令不会覆盖旧命令；新收到的 `stop` 命令会优先覆盖 pending，降低急停被挡住的风险。
- `User/usart/bsp_debug_usart.h`
  - 不再对外暴露 `UART_RxBuffer`。
- `User/stm32f4xx_it.c`
  - `DEBUG_USART_IRQHandler()` 不再直接写 `UART_RxBuffer/UART_RxPtr/status.cmd`。
- `User/stepper/bsp_device_usart_ctl.c`
  - `DealSerialData()` 先取出本地命令副本，再分发 ROS 或人工命令。

当前限制：

- pending 只保存一条完整命令。极端高速连续下发普通命令时，后续命令可能被丢弃，但不会覆盖正在等待处理的命令。

## 风险4：步进 ISR 共享状态

当前步进 ISR 共享状态已经去 bitfield，并增加快照读取：

- `User/stepper/bsp_stepper_T_speed.h`
  - `speedRampData` 的 `run_state/dir/continuous/speed_update_pending/target_dir/stop_on_target` 改为普通 `uint8_t` 字段。
  - `GLOBAL_FLAGS` 改为普通 `volatile uint8_t` 字段。
  - 新增 `StepperRuntimeSnapshot`。
- `User/stepper/bsp_stepper_T_speed.c`
  - `srd[]`、`stepPosition[]`、`status`、`motor_status[]` 声明为 `volatile`。
  - 新增 `Stepper_GetRuntimeSnapshot()`，在短临界区内复制运行状态。
- `User/stepper/bsp_device_usart_ctl.c`
  - `Device_Task()` 使用快照同步电机位置、使能和运行状态。
- `User/stepper/bsp_stepper_ctl.c`
  - 运行中调速、连续运行方向判断、`set` busy 判断使用快照。

效果：

- 降低主循环读取到旧状态或半更新状态的风险。
- 避免 bitfield 在 ISR 和主循环之间发生读改写覆盖。

## 风险5：后台监控同步通信

当前仍保留同步 UART 通信，不做非阻塞协议重构。已实施的处理是：后台快速检测连续两次通信失败才报 fault，第一次失败只 warning。

夹爪保持：

- 位置：`User/gripper/bsp_clamp_ctl.c`
- 周期：`DEVICE_FAST_CHECK_INTERVAL_MS = 200U`
- 第一次 `BusServo_ReadStatus()` 失败：

```text
@warn dev=clamp event=status_error result=<result> servo_err=0xXX fail_count=1 action=retry
```

- 连续第二次失败：

```text
@fault dev=clamp event=status_error result=<result> servo_err=0xXX fail_count=2 action=torque_off
```

- 第二次失败后会结束夹爪 hold，标记 `DEV_ERROR`，并尝试关闭夹爪扭矩。
- 任意一次读取成功都会清零通信失败计数。

吸盘保持：

- 位置：`User/vacum/bsp_vacum_ctl.c`
- 周期：`DEVICE_FAST_CHECK_INTERVAL_MS = 200U`
- 第一次 `Evs08_ReadStatus()` 失败：

```text
@warn dev=vacum event=status_error result=<result> fail_count=1 action=retry
```

- 连续第二次失败：

```text
@fault dev=vacum event=status_error result=<result> fail_count=2 action=stop
```

- 第二次失败后会结束吸盘 hold，标记 `DEV_ERROR`，并尝试 `Evs08_Stop()`。
- 任意一次读取成功都会清零通信失败计数。

当前限制：

- 单次舵机/Modbus 读写仍然是同步阻塞；本次修复只降低偶发通信抖动误报 fault 的概率。
- 手动 `status/readreg` 和 ROS status 仍然按命令同步读取并立即返回结果。

## 风险6：Fault 后永久停死

当前已经引入 IWDG，并修改 Fault Handler 为最小安全处理后等待看门狗复位。

实现位置：

- `User/main.c`
  - 初始化完成并打印帮助后调用 `Safety_WatchdogInit()`。
  - 主循环完成 `DealSerialData()`、`Device_Task()`、`Device_ReportDone()` 后调用 `Safety_WatchdogRefresh()`。
- `User/stm32f4xx_it.c`
  - `Safety_WatchdogInit()` 使用 `HAL_IWDG_Init()` 初始化看门狗。
  - `Safety_WatchdogRefresh()` 使用 `HAL_IWDG_Refresh()` 喂狗。
  - `HardFault_Handler()`、`MemManage_Handler()`、`BusFault_Handler()`、`UsageFault_Handler()` 统一进入 `Safety_HandleFault()`。
  - Fault 中关闭 TIM8 步进比较输出和中断，直接把两路步进 ENA 置为 OFF。
  - Fault 信息写入 BKPSRAM，复位后通过 `Safety_ReportLastFault()` 打印一次。
- `User/stm32f4xx_it.h`
  - 声明安全看门狗和上次 fault 上报接口。
- `User/stm32f4xx_hal_conf.h`
  - 打开 `HAL_IWDG_MODULE_ENABLED`。
- `Project/Fire-F407.uvprojx`
  - 将 `stm32f4xx_hal_iwdg.c` 加回 `STM32F4xx_HAL_Driver` 编译组。

IWDG 参数：

- 使用 IWDG 分频 256。
- reload 为 1874，按 LSI 约 32kHz 估算约 15s。
- 选择约 15s 是为了兼容当前仍存在的阻塞式夹爪动作，避免正常长动作被误复位。

Fault 后动作：

1. 关闭普通中断。
2. 关闭步进 TIM8 输出比较通道和对应中断。
3. 两路步进 ENA 置为 OFF，使步进驱动脱机。
4. 保存 `fault_type/CFSR/HFSR/MMFAR/BFAR` 到 BKPSRAM。
5. 如果 IWDG 已启动，进入 `while(1)`，不再喂狗，等待 IWDG 复位。
6. 如果 Fault 发生在 IWDG 启动前，则执行 `NVIC_SystemReset()`，避免永久卡死。

复位后，如果检测到上次 fault 记录，会打印：

```text
@fault dev=system event=last_fault type=<hard|mem|bus|usage> cfsr=0xXXXXXXXX hfsr=0xXXXXXXXX mmfar=0xXXXXXXXX bfar=0xXXXXXXXX reset=<iwdg|other>
```

如果只有 IWDG reset 标志但没有 fault 记录，会打印：

```text
@fault dev=system event=last_reset reset=iwdg
```

当前限制：

- Fault Handler 中不会尝试夹爪 torque off 或吸盘 stop，因为这些动作依赖阻塞式串口通信，Fault 上下文里不安全。
- BKPSRAM 记录依赖芯片备份 SRAM 可用；若备份域供电或访问异常，复位后可能只能看到 IWDG reset 标志。

## 后续建议

- 若后续要求更快的 Fault 自动恢复，可在拆掉主要阻塞命令或补充长动作内部喂狗后，再把 IWDG 时间从约 15s 缩短。
- 若后续要求 stop 命令在外设通信阻塞期间也能立即响应，需要把舵机和 Modbus 通信改成非阻塞状态机。
