# 后续实现

本文记录已经讨论过、但当前代码尚未实现的后续功能，便于后续开发时回溯设计意图。

## 夹爪 PI 保力软保护

目标：在夹爪 PI 保持夹持力时，避免舵机负载长时间接近或超过 `80%` 过载保护阈值，减少舵机进入内部过载保护的概率。

当前舵机初始化保护参数：

| 参数 | 地址 | 当前值 | 含义 |
| --- | --- | --- | --- |
| 保护扭矩 | `34 / 0x22` | `20` | 进入过载保护后的输出扭矩为最大扭矩的 `20%` |
| 保护时间 | `35 / 0x23` | `200` | 过载持续 `2s` 后进入保护 |
| 过载扭矩 | `36 / 0x24` | `80` | 负载达到最大扭矩 `80%` 时开始过载计时 |

建议增加一层 PI 软保护区，不做“立即松开”的强动作，只限制继续夹紧：

```text
750 <= load_abs < 780:
  进入软保护区
  禁止正向积分继续增大
  正向 delta_pos 最大限制为 +2
  负向 delta_pos 正常允许

load_abs < 730:
  退出软保护区
  恢复正常 PI
```

设计要点：

- `750` 为软保护进入阈值，低于硬件 `80%` 过载阈值，给传感器波动、机械弹性和 PI 过冲留出余量。
- `730` 为软保护退出阈值，与进入阈值形成迟滞，避免负载在边界附近来回抖动。
- 软保护区内，如果 `error > 0`，说明目标负载还没达到，但已经接近保护区，此时不再继续增加正向积分，并将正向 `delta_pos` 限制到 `+2`。
- 软保护区内，如果 `error <= 0`，说明负载已经达到或超过目标，允许 PI 正常输出负向 `delta_pos` 去松开。
- 不使用“立即松开”动作，避免负载突变、夹持不稳定或干扰掉落检测。

可能收益：

- 减少 PI 积分继续把夹爪推向 `80%` 以上过载区。
- 高负载目标下控制更平滑，不会因为强制退开造成负载大幅波动。
- 日后可以通过日志明确区分“正常 PI 调整”和“接近过载时的软限幅调整”。

可能风险：

- 如果负载已经因为过冲超过 `80%`，该方案只限制继续夹紧，不会主动快速退让，仍可能触发舵机内部过载保护。
- 高负载目标可能收敛变慢，甚至稳定在 `730~760` 附近而达不到更高目标。
- 如果负载读数本身波动较大，软保护区仍可能频繁进入和退出，需要根据实测调整 `750/730` 阈值。

后续实现建议：

- 在 `Clamp_HoldCalcDelta()` 或其调用链中加入软保护状态标志。
- 增加日志，例如：

```text
@event level=info dev=clamp event=hold_guard load=-760 target=750 error=-10 delta=0 pos=xxxx
```

- 首版只实现软限幅，不加入立即松开和掉落检测屏蔽逻辑。

## 步进电机电源状态和疑似堵转检测

目标：当前 `mtor1/mtor2` 没有驱动器状态反馈，LED1/LED2 只能表示 MCU 侧控制状态，无法判断驱动器是否上电、掉电或异常重载。

当前阶段不做位置闭环，只需要：

- 检测驱动器上电/下电。
- 检测运行中疑似堵转或异常重载。
- 将结果用于 LED 状态和 ROS/串口事件上报。

### 电源功率检测方案

在步进驱动器电源输入端检测电压和电流，计算近似输入功率：

```text
Pbus = Vbus * Ibus
```

可判断：

- `Vbus` 正常：驱动器电源存在。
- `Vbus` 低于阈值：驱动器下电、掉电或电源断线。
- `Ibus/Pbus` 异常升高：运行中疑似堵转、卡滞或负载过大。
- `Ibus/Pbus` 异常过低：驱动器未供电、使能异常或电机未实际输出。

注意：步进驱动器通常是恒流斩波控制，输入功率和电机实际力矩不是严格线性关系。因此该方案适合做 `stall_suspect`，不适合声明为精确堵转检测。

### 硬件建议

优先选型：

- `INA219/INA226`：I2C，直接读取电压、电流和功率，调试方便。
- `INA180/INA181 + ADC`：模拟电流检测，成本低、响应快。
- 霍尔电流传感器：隔离较好，但小电流精度通常一般。

如果使用采样电阻：

- 采样电阻阻值要小，避免驱动器供电压降。
- 按最大电流校核电阻功耗。
- 优先高边采样，避免抬高系统地。
- ADC 前增加 RC 滤波。
- 软件做滑动平均、连续命中和阈值迟滞。

### 建议判定逻辑

```text
Vbus < power_off_threshold:
  power_state = off
  LED = off

Vbus 正常 && Ibus/Pbus 在正常范围:
  power_state = on
  LED = on

运行中 && Pbus 连续 N 次超过 high_power_threshold:
  event = stall_suspect
  LED = blink

运行中 && Vbus 正常但 Ibus/Pbus 长时间过低:
  event = output_suspect
  LED = blink
```

建议事件：

```text
@event level=fault dev=mtor1 event=power_lost ...
@event level=warn  dev=mtor1 event=stall_suspect ...
@event level=warn  dev=mtor1 event=output_suspect ...
```

### 软件接入建议

- 新增 `StepperPowerMonitorTask()`，周期读取两路驱动器电源检测值。
- `DeviceStepperStatus` 增加 `power_state`、`vbus`、`ibus`、`pbus`、`power_fault` 字段。
- `mtor status` 和 ROS `@state` 增加电源检测字段。
- LED1/LED2 根据电源检测结果显示：
  - 常亮：驱动器电源正常。
  - 常灭：驱动器下电或断线。
  - 闪烁：疑似堵转、异常重载或输出异常。

首版建议只做电源电压 + 输入电流/功率检测。编码器反馈属于后续更高等级的位置闭环方案，不作为当前目标。
